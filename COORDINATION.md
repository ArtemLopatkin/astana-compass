# Координация внешних агентов

## Старт

Владелец репозитория: `chinusoid`. Репозиторий: https://github.com/chinusoid/astana-compass.

Сейчас он приватный. Участник должен принять GitHub invitation под собственным аккаунтом. Доступ к ChatGPT/Codex и доступ к GitHub — разные вещи. Координатор не передаёт свой token другим агентам. Пока логины участников не предоставлены, приглашения не отправлены.

Передайте каждому внешнему агенту **один** файл `TASK-*.md` целиком. Все задания содержат ссылку на репозиторий, правила, область записи и критерии завершения. Для работы с одним аккаунтом GitHub на нескольких компьютерах всё равно используйте отдельные ветки и собственные локальные clone/worktree.

## Порядок PR

1. **Foundation:** координатор объединяет общие manifests, generation shared models/clients, миграции, contract fixtures и минимальный CI. Агент 07 предлагает конфигурацию, 04 предлагает backend dependencies, 05 — frontend dependencies. До этого они могут готовить независимый код в своих ветках, тестируя по seed fixtures.
2. **Data + ports:** 01 поставляет idempotent ingestion и repository adapter; 02 — retrieval по протоколу; 03 — context adapters. Их первые PR можно review независимо.
3. **Вертикальная интеграция:** 04 соединяет модули; 05 подключает живой API. 06 проверяет contracts и сквозные сценарии. Реальные данные и live/degraded режимы явно различаются.
4. **Расширения:** мультиязычность, планы 1–3 остановок, групповая совместимость предпочтений, погода, диалоговые правки, доступность, explainability.
5. **Release:** 07 развёртывает в выбранной среде после проверки, 08 готовит демонстрацию и пакет защиты по фактическим результатам, 06 публикует измеренный отчёт.

Порядок не запрещает параллельную работу. Он задаёт зависимости merge. Новые функции не должны ломать уже интегрированный маршрут пользователя.

## Что делает координатор при каждом PR

- Сверяет изменённые пути с `AGENTS.md` и проверяет отсутствие неожиданных секретов/дампов.
- Проверяет совместимость с canonical contract и согласованные зависимости.
- Запускает относящиеся к изменению проверки и короткий интеграционный сценарий.
- Проверяет реальные claims: источники, неизвестность, ограничения, честность degraded mode.
- Принимает небольшой понятный PR, затем обновляет интеграционную ветку/`main` и сообщает исходный SHA следующим агентам.

Merge выполняется владельцем/координатором после review. Самостоятельное одобрение автором не заменяет независимую проверку.

При первоначальной настройке 2026-10-18 GitHub сообщил, что branch protection не будет применяться к этому приватному репозиторию на текущем тарифе аккаунта. Поэтому сейчас обязательный PR/review — процессное правило, а не техническая гарантия. Координатор не менял публичность и не покупал подписку. Техническое применение правил проверяется повторно, если владелец изменит доступность репозитория или тариф.

## Статус начального репозитория

Подготовлены product/architecture specification, правила сотрудничества, восемь заданий и seed-контракты. Runtime, CI, deployment, branch protection и приглашения участников считаются готовыми **только после отдельной проверки**, не из-за наличия этих документов.
